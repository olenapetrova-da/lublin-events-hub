# Strategy v4 — Minimal Make Ops (2025-10-28)

**Goal:** Daily refresh with **zero** Make operations; serve user queries with **1 HTTP** from Make to your Apps Script API.

## What exists (facts)
- **official adapter**: list+details; `Payment for Entry` uses Polish labels: “Bezpłatny” / “Płatny” (empty when unknown). Subrequest-safe. No image URL in payload.
- **zoom adapter**: list only; `Payment for Entry` = `Yes` / `No` (empty when unknown). Carries `_EndDate` from `data-end-date`.
- **hub**: merges sources, dedupes showtimes; when `sheet=1` it emits **rows**; when `sheet=0` it returns **JSON** `events[]`.
  - Row order (sheet mode): `Title, Date, Time, Venue, Category, Link, Image URL, Payment for Entry, Source`.

## Target architecture (low-ops)
### A) Data refresh (Apps Script time trigger, daily)
- `refresh()` calls the hub **once** for a 7‑day window (e.g., `?date=YYYY-MM-DD&period=week&group_times=1&sheet=0&pages=3&limit=1000`).
- Parse JSON `events[]`; write to **staging** tab `raw_events` with **10 columns**:
  `Title, Date, Time, Venue, Category, Link, Image URL, Payment for Entry, Source, _EndDate`
  - If a source doesn’t have `_EndDate`, set `_EndDate = Date`.
- Call `materialize()` to produce normalized **`events`** table with columns:
  `event_id, title, start_dt, end_dt, venue, payment, categories, source, url`.

### B) Serving user requests (Apps Script Web App)
- `doGet(e)` reads **`events`**, applies filters (date/period/payment/category/limit/offset), and returns JSON.
- Make/Telegram flow = **parse text → 1 HTTP → send message**.

## Normalization rules
- **Title/Venue**: trimmed strings.
- **Datetime**:
  - `start_dt` = combine `Date + Time` (if no time → start-of-day). Use *Europe/Warsaw*.
  - `end_dt` = if `_EndDate` present, use it; else = `Date`. If a time range exists, use end time; else end-of-day.
- **Payment mapping**:
  - official: “Bezpłatny” → `free`, “Płatny” → `paid`, empty → `unknown`
  - zoom: `No` → `free`, `Yes` → `paid`, empty → `unknown`
- **Categories**: map raw `Category` via `taxonomy_map` (exact → contains → regex), then aliases via `taxonomy_alias`.
  - Join multi-hit canonicals with `|` (pipe). If none → `other`.
- **IDs**: `event_id = sha1(source + "|" + normalize(title) + "|" + start_dt + "|" + normalize(venue))`

## API surface (Apps Script)
- **Refresh**: time-based trigger → `refresh()` → `materialize()`.
- **Query**: `doGet(e)` params:
  - `date` (YYYY-MM-DD), `period` (`day|week|range|weekend`), `days` (int, optional)
  - `payment` (`any|free|paid`), `category` (comma‑separated, aliases ok)
  - `limit` (default 30), `offset` (default 0)
- **Response**:
```json
{
  "start": "2025-10-28",
  "end": "2025-11-03",
  "total": 123,
  "limit": 30,
  "offset": 0,
  "results": [
    {
      "event_id": "…",
      "title": "…",
      "start_dt": "2025-10-29T18:00:00+01:00",
      "end_dt": "2025-10-29T20:00:00+01:00",
      "venue": "…",
      "payment": "free|paid|unknown",
      "categories": "kids|workshop",
      "source": "lublin.eu",
      "url": "https://…"
    }
  ]
}
```

## Sheets (final layout)
- **raw_events** (staging, 10 columns):
  `Title, Date, Time, Venue, Category, Link, Image URL, Payment for Entry, Source, _EndDate`
- **events** (normalized, 9 columns):
  `event_id, title, start_dt, end_dt, venue, payment, categories, source, url`
- **taxonomy_map**: `source, source_key, source_label, match_type, canonical, notes`
- **taxonomy_alias**: `alias, canonical`
- **taxonomy_unmapped**: `source, raw_label, count`

## Make usage
- **Daily refresh**: none (0 ops).
- **Per user request**: 1 HTTP (to Apps Script) + 1 Send Message.

## Milestones
1. Apps Script `refresh()` writes to `raw_events` (verify rows appear).
2. `materialize()` generates `events` with mapped categories and payment.
3. `doGet` returns filtered JSON; Telegram scenario calls it with 1 HTTP.
